# 의사록 자동작성 — 발전 방향 설계 요약

> 이 문서는 `grilling`(압박 인터뷰) 과정을 통해 합의한 설계 결정을 기록한 것이다.
> 모든 데이터·사례는 교육용 가상(더미)이며, 실제 회사·인물·사건과 무관하다.

## 1. 목적지와 산출물

| 항목 | 결정 |
| --- | --- |
| **목적 (Q1)** | 교육 샘플을 넘어 **실제 업무용 내부 운영 도구**로 발전. 단 당분간은 가상 더미 데이터로만 검증 |
| **산출물 (Q2)** | 최종 결과물은 **공식 양식 `.docx` 의사록**. 웹앱(Streamlit)은 생성·검토·확정용 **작업 화면** |
| **데이터·보안 (Q3)** | 실데이터(실명·주민번호·고객명·녹취)는 **리포/클라우드 반입 금지**. 실데이터 처리는 사내 폐쇄망에서만 |

## 2. 구현 원칙

- **출력 엔진 (Q4)** — `docxtpl` 템플릿 채우기 유지. 양식 변경은 **코드가 아니라 `.docx` 템플릿 교체**로 관리하여 비개발자도 수정 가능.
- **신뢰 게이트 (Q5)** — 휴먼-인-더-루프 필수. 확정 전에는 **'초안'** 표시, 담당자 확정(R14) 후에만 **'확정본'** 발행. AI는 초안만, 책임은 사람.
- **실행 환경 (Q6)** — 운영은 **사내 폐쇄망 온프레 Streamlit**. `run.bat`은 개발·시연용.
- **AI 접근 (Q7)** — 1순위: `api.anthropic.com`만 허용하는 **화이트리스트 egress + Claude API**. 외부 반출이 절대 불가로 판정되면 **온프레 sLLM**으로 선회.
- **템플릿 관리 (Q8)** — 양식 `.docx`를 `templates/` 폴더로 **분리·버전관리**하고 `settings.json`의 `template` 값으로 선택.
- **마스킹 (Q9)** — 전송 전 **가역 토큰 치환(→전송→복원)**. 주민등록번호는 **미전송**.
- **모델 (Q10)** — 기본 **Sonnet**, 어려운 건만 **Opus 폴백**. `settings.json`/`.env`에서 교체 가능.
- **감사 추적 (Q11)** — AI 원안 ↔ 담당자 최종본 diff, 확정자·시각을 **감사 로그**로 보존(금융 감독·분쟁 대응 근거).

## 3. 실행 계획

1. **(완료, 본 변경) Q12-A** — 더미 데이터로 **end-to-end `.docx` 생성 파이프라인 완성 + 템플릿 폴더 분리**.
   - `generate.py` : 녹취 → 추출(모의/AI) → 규칙검증(R1~R14) → 초안·확정 `.docx` 생성 (헤드리스 CLI)
   - `templates/금소위_기본.docx` : 양식 템플릿 분리, `settings.json`의 `template`로 선택
   - `core/config.py` : `TEMPLATE_DIR`, `Settings.template`, `template_path()` 추가
2. **(다음) Q12-B** — 마스킹 모듈, 감사 로그 모듈.

## 4. 이번 범위 밖 (Q13)

실데이터 연동, 사내 SSO·권한관리, 폐쇄망 인프라 구축·보안팀 승인 절차.
→ 이번 작업은 **코드·구조·더미 검증·설계까지**. 실데이터·인프라·보안승인은 사내 몫으로 분리.
