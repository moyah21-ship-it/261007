# Claude Code 단계별 프롬프트 (교육 당일 복사·붙여넣기용)

> 이 폴더(PoC_더미데이터)를 프로젝트 폴더의 `data/` 하위에 복사한 뒤, 프로젝트 폴더에서 `claude`를 실행하고 아래 프롬프트를 순서대로 입력합니다.
> 각 단계가 끝날 때마다 화면에서 직접 실행해 결과를 확인한 후 다음 단계로 넘어갑니다.

---

## STEP 0. 프로젝트 이해시키기 (약 10분)

```
나는 금융소비자보호위원회 의사록 작성 담당자야. 회의 녹취 텍스트를 넣으면
의사록 초안(.docx)을 자동으로 만들어 주는 웹앱 PoC를 오늘 하루 안에 만들고 싶어.

data/ 폴더의 파일을 모두 읽고 구조를 파악해 줘.
- 01_위원명단.csv, 02_회의정보.csv, 03_안건목록.csv : 기준정보
- 04-1_회의녹취록_발언자표시.txt : 입력 녹취록 (메인)
- 04-2_회의녹취록_화자번호.txt : 화자 이름이 없는 녹취록 (확장 테스트용)
- 06_의사록양식.docx : 출력 양식 ({{ }} 자리표시자 포함)
- 07_의사록_정답예시.docx : 기대 결과물 (검증 기준)

기술 스택은 Python + Streamlit + python-docx(docxtpl) + Anthropic Claude API로 하고,
API 키가 없을 때도 시연할 수 있도록 '모의(mock) 모드'를 함께 만들어 줘.
코드는 아직 작성하지 말고, 화면 구성과 처리 흐름을 먼저 계획으로 보여 줘.
```

## STEP 1. 기준정보·녹취록 불러오기 (약 30분)

```
1단계를 구현해 줘.
- 사이드바에서 위원명단/회의정보/안건목록 CSV와 녹취록 TXT를 업로드(또는 data/ 기본 파일 자동 로드)
- 녹취록의 각 줄을 [시각] 발언자: 발언 형식으로 파싱해서 표로 보여 줘
  (컬럼: line_no, time, speaker_label, speaker_id, utterance)
- speaker_label을 위원명단의 name/role/alias와 매칭해 speaker_id를 붙이고,
  매칭 실패한 줄은 빨간색으로 표시해 줘.
- 회의 개요(재적, 출석, 불참, 이석, 정족수 충족 여부)를 계산해서 상단에 보여 줘.
```

## STEP 2. AI 추출 (약 60분)

```
2단계를 구현해 줘.
- 파싱된 녹취록 + 안건목록 + 위원명단을 Claude API에 보내서 아래 JSON 스키마로 추출해 줘.
  {
    "agendas": [{
      "agenda_id": "AG-01",
      "summary": "제안설명 요지 (2~3문장)",
      "discussions": [{"speaker_id": "M02", "type": "질의|의견|답변|요청", "content": "요지", "source_lines": [7]}],
      "decision": "보고접수|원안가결|수정가결|조건부가결|부결|보류",
      "decision_condition": "조건/수정 내용 (없으면 빈 문자열)",
      "votes": {"for": ["M01"], "against": [], "abstain": []},
      "follow_ups": [{"task": "", "owner_dept": "", "due": "YYYY-MM-DD 또는 미정", "source_lines": []}]
    }]
  }
- 잡담·인사·진행 멘트는 제외하고, 발언 요지는 의사록 문체(~함, ~임)로 바꿔 줘.
- '다음 주 금요일', '12월 말' 같은 상대 날짜는 회의일 기준으로 YYYY-MM-DD로 바꿔 줘.
- 발언 중 '정정하겠습니다'가 있으면 정정된 값만 사용해 줘.
- API 키가 없으면 data/mock_result.json을 읽어 같은 화면이 나오게 해 줘
  (mock_result.json은 07_의사록_정답예시.docx 내용을 기준으로 네가 만들어 줘).
```

## STEP 3. 규칙 검증 (약 40분)

```
3단계를 구현해 줘. AI 추출 결과를 아래 규칙으로 검증하고, 위반 항목을 경고 목록으로 보여 줘.
- R1 정족수: 출석 의결권 위원 수 > 재적 의결권 위원 수 / 2
- R2 의결: 찬성 수 > 표결 시점 출석위원 수 / 2 (이석자 제외)
- R3 표결 합계: 찬성+반대+기권 = 표결 시점 출석위원 수
- R4 모든 안건에 결과(decision)가 있어야 함
- R5 보고안건은 '보고접수', 의결안건은 가결/부결/보류 계열이어야 함
- R6 후속조치는 담당부서와 기한이 모두 있어야 함 (없으면 '확인 필요' 표시)
- R7 출석 명단에 없는 사람이 발언자로 추출되면 경고
- R8 모든 발언 요지에 원문 줄번호(source_lines)가 있어야 함
```

## STEP 4. 검토·수정 화면 + 의사록 생성 (약 60분)

```
4단계를 구현해 줘.
- 안건별 탭에서 AI 추출 결과를 표로 보여 주고, 담당자가 직접 수정할 수 있게 해 줘.
- 각 발언 요지 옆에 원문 줄을 펼쳐 볼 수 있게 해 줘.
- [의사록 생성] 버튼을 누르면 06_의사록양식.docx에 값을 채워 .docx로 다운로드되게 해 줘.
- 생성 결과를 07_의사록_정답예시.docx와 비교해서 안건 결과·표결 수·후속조치 개수가 일치하는지 보여 줘.
```

## STEP 5. (시간이 남으면) 확장

```
04-2_회의녹취록_화자번호.txt처럼 이름 없이 '화자1, 화자2'로만 된 녹취록이 들어오면,
발언 내용(호칭, 소속 언급, 진행 멘트 등)을 근거로 화자를 위원명단에 매핑하는 제안 화면을 만들어 줘.
AI가 제안한 매핑과 근거를 보여 주고, 담당자가 드롭다운으로 확정하게 해 줘.
```
