시스템 아키텍처 & 설계

녹취 텍스트를 받아 안건별 내용을 추출하고, 업무규칙으로 교차검증한 뒤, 담당자 확정을 거쳐 공식 양식의 의사록 .docx를 생성하는 파이프라인. 아래 설계는 압박 인터뷰(grilling)로 합의한 결정을 반영한다.

내부 운영 도구 지향 산출물 = .docx 휴먼-인-더-루프 교육용 더미 데이터

처리 파이프라인

generate.py 한 번으로 아래 5단계가 헤드리스로 실행된다. Streamlit 웹앱은 같은 흐름을 사람이 보며 조작하는 작업 화면이다.

STEP 1입력 로드 위원명단·회의정보·안건·녹취록을 읽어 발언자를 매핑 core/loader · meeting →
STEP 2AI 추출 안건별 요지·발언·처리결과·후속조치 구조화 (키 없으면 모의 모드) core/extractor →
STEP 3규칙검증 R1~R14로 정족수·표결·기한·근거를 교차검증, 경고 산출 core/rules →
STEP 4 · 게이트담당자 확정 사람이 수정·확정(R14). 확정 전엔 '초안', 확정 후 '확정본' human-in-the-loop →
STEP 5의사록 생성 선택한 양식 템플릿을 채워 .docx 발행 core/render · templates/
⚠ AI는 초안만 생성 — 최종 책임은 담당자 확정(R14)에 있다

핵심 모듈

책임을 모듈로 분리해, 규칙·양식·모델을 코드 수정 없이 바꿀 수 있다.

generate.py
end-to-end CLI. 추출→검증→초안·확정 .docx 생성. --ai / --template / --out
core/loader.py
CSV·녹취록 파싱, 발언자 매핑(R11). UTF-8/CP949 인코딩 처리
core/meeting.py
재적·출석·이석·정족수 계산(R1·R3·R13), 표결 시점 출석 산정
core/extractor.py
Claude API 추출 + 모의 모드. JSON 오류 시 1회 재요청·정규화
core/rules.py
업무규칙 R1~R14 검증. 경고/정보 분류로 신뢰 게이트 지원
core/render.py
docxtpl로 양식 템플릿을 채워 .docx 생성, 초안/확정 표시(R14)
templates/
양식 .docx 분리·버전관리. settings의 template로 선택
core/config.py
정족수·가결 기준·모델·템플릿을 코드와 분리(settings.json)

설계 결정 (grilling 합의)

압박 인터뷰로 확정한 13개 결정. 각 결정이 구현 원칙의 근거가 된다.

Q1 · 목적지
내부 운영 도구로 발전
교육 샘플을 넘어 실제 업무용. 단 당분간 더미 데이터로만 검증
Q2 · 산출물
.docx 가 최종 결과물
웹앱은 생성·검토·확정용 작업 화면
Q3 · 데이터 경계
실데이터 반입 금지
실명·주민번호·녹취는 리포/클라우드 밖, 사내 폐쇄망에서만
Q4 · 출력 엔진
docxtpl 템플릿
양식 변경은 코드 아닌 .docx 템플릿 교체로
Q5 · 신뢰 게이트
휴먼-인-더-루프
확정(R14) 후에만 '확정본'. AI는 초안만
Q6 · 실행 환경
폐쇄망 온프레
운영은 사내 Streamlit, run.bat은 개발용
Q7 · AI 접근
화이트리스트 egress
api.anthropic.com만 허용 + Claude API, 불가 시 온프레 sLLM
Q8 · 템플릿 관리
폴더 분리·버전관리
회사·위원회별 템플릿을 settings에서 선택
Q9 · 마스킹
가역 토큰 치환
전송 전 치환→복원, 주민번호는 미전송
Q10 · 모델
Sonnet + Opus 폴백
기본 Sonnet, 어려운 건만 Opus, 설정으로 교체
Q11 · 감사 추적
원안↔최종 diff 보존
확정자·시각 감사 로그로 규제 대응
Q12 · 실행 순서
파이프라인 먼저
A 완료(파이프라인+템플릿), B 마스킹·감사로그는 다음

작업 범위 (Q13)

✓ 이번 범위

  • 동작하는 .docx 생성 파이프라인
  • 양식 템플릿 분리 구조
  • 더미 데이터 검증 · 규칙검증
  • 설계 문서화

✗ 범위 밖 (사내 몫)

  • 실데이터 연동
  • 사내 SSO · 권한관리
  • 폐쇄망 인프라 구축
  • 보안팀 승인 절차
